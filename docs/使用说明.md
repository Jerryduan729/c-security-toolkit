# 使用说明

本手册面向第一次接触这个工具的人，按「装好 → 跑起来 → 接进流程 → 出问题怎么查」的顺序写。
项目背景与规则设计见 [README](../README.md)，答辩演示流程见 [答辩演示](答辩演示.md)。

- 版本：1.2.0
- 环境：Python 3.10 及以上（CI 在 3.10 / 3.12 上验证）
- 依赖：无，全部使用标准库

---

## 一、准备

这台电脑没有 Python？直接用 Releases 里的免安装版，见 [跨平台运行](跨平台运行.md)，可以跳过本节。

```bash
cd 安全
python3 --version      # 确认 3.10+
python3 -m unittest    # 68 项测试，首次使用先跑一遍确认环境正常
```

预期最后一行是 `OK`。如果这里就失败，先别往下走，按「七、常见问题」排查。

三种用法，按需要选：

| 方式 | 适合场景 | 启动命令 |
| --- | --- | --- |
| 命令行 | 快速自查、接 CI | `python3 security_scan.py --authorized --source 目录` |
| 网页界面 | 演示、边看边改 | `./run.sh` |
| AI 分析 | 想知道「为什么危险、怎么改」 | 命令行加 `--ai`，或网页点按钮 |

> 所有扫描都必须带 `--authorized`，表示目标由你拥有或已获书面授权。这不是形式，是使用前提。

## 二、命令行：扫描源码

### 2.1 最基本的用法

```bash
python3 security_scan.py --authorized --source examples
```

输出：

```
共发现 9 条结果（CRITICAL 1，HIGH 4，MEDIUM 4）

[CRITICAL] SEC-101 禁用 gets examples/vulnerable_demo.c:27
  gets 无法限制输入长度，必然导致缓冲区溢出，C11 起已被移除。
  代码：gets(name);   /* SEC-101：无长度限制，必然栈溢出 */
  CWE-242 · 修复：fgets(buf, sizeof buf, stdin) 并检查返回值
```

每条结果包含：级别、规则编号、问题名、`文件:行号`、命中代码、CWE 分类、修复建议。

### 2.2 常用组合

```bash
# 只看高危
python3 security_scan.py --authorized --source src --min-severity HIGH

# 单个文件
python3 security_scan.py --authorized --source src/login.c

# 跳过第三方目录（可重复）
python3 security_scan.py --authorized --source . --exclude 'vendor/*' --exclude 'build/*'

# 生成 Markdown 报告
python3 security_scan.py --authorized --source src --format markdown --output report.md

# 输出 JSON 给脚本消费
python3 security_scan.py --authorized --source src --format json

# 输出 SARIF 给 GitHub Code Scanning / SonarQube
python3 security_scan.py --authorized --source src --format sarif --output report.sarif
```

### 2.3 扫描线上地址

```bash
python3 security_scan.py --authorized --url https://example.com
```

会检查：明文 HTTP、安全响应头、HSTS 时长、Cookie 的 `Secure/HttpOnly/SameSite`、证书有效期、
TLS 版本、重定向是否降级或指向内网。

出于安全设计，**私网、回环、链路本地地址一律拒绝**：

```
错误：出于安全限制，禁止扫描私网、回环、链路本地或保留地址
```

这是刻意为之，防止工具被当成 SSRF 跳板。本地服务请用单元测试里的 mock 方式验证。

## 三、网页界面

```bash
./run.sh              # 等价于 python3 web_app.py --open
./run.sh --port 8800  # 端口被占用时换一个
```

浏览器打开 `http://127.0.0.1:8765` 后：

1. 左侧「源码路径」填 `examples` 或你的目录，点「开始扫描」（也可按 `⌘/Ctrl + Enter`）
2. 右侧看汇总卡片和结果列表，每条带 CWE 与修复建议
3. 点「生成 AI 分析」得到风险解释与修复代码，下方输入框可继续追问
4. 点「导出 HTML 报告」，自动在 `reports/` 生成带打印样式的文件并打开

界面只监听 `127.0.0.1`，每次启动生成一次性令牌校验写操作；关掉终端即停止服务。

## 四、接入 AI

### 4.1 配置

```bash
export SECURITY_AI_API_KEY=sk-xxxxxxxx
```

只配这一项默认走 OpenAI。换服务时同时给地址和模型：

| 服务 | 命令 |
| --- | --- |
| DeepSeek | `export DEEPSEEK_API_KEY=sk-...`（自动识别，无需其它配置） |
| 通义千问 | `--ai-base-url https://dashscope.aliyuncs.com/compatible-mode/v1 --ai-model qwen-plus` |
| Kimi | `--ai-base-url https://api.moonshot.cn/v1 --ai-model moonshot-v1-8k` |
| Ollama 本地 | `--ai-base-url http://localhost:11434/v1 --ai-model qwen2.5-coder:7b --ai-key ollama` |

环境变量是 `SECURITY_AI_API_KEY` / `SECURITY_AI_BASE_URL` / `SECURITY_AI_MODEL`，
优先级：命令行参数 > 环境变量 > 默认值。

### 4.2 三种用法

```bash
# 分析扫描结果
python3 security_scan.py --authorized --source src --ai

# 直接审查一个文件（不走规则）
python3 security_scan.py --authorized --source src --ai-review src/login.c

# 分析后继续追问
python3 security_scan.py --authorized --source src --ai --ai-chat
```

网页界面里配好环境变量后**重启服务**，左下角提示会从「未检测到 API Key」变成模型名。

### 4.3 省钱的三个参数

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `--ai-max-findings` | 20 | 最多送多少条结果 |
| `--ai-context-lines` | 2 | 每条附带几行代码上下文 |
| `--ai-output FILE` | 无 | AI 文本单独存一份 |

### 4.4 隐私边界

- 只发扫描结果与命中行附近的代码，不发整库；`--ai-review` 例外（单文件，超 12000 字符截断）
- `password="..."`、`api_key="..."` 的值和 PEM 私钥块在进入提示词前替换为 `***`
- 远程接口强制 HTTPS，本地模型可用 `http://localhost`
- 没配 Key、断网、限流都只提示，不影响扫描结果与退出码

## 五、接入 CI 与基线

### 5.1 失败阈值

```bash
python3 security_scan.py --authorized --source src --fail-on high
```

可选 `none / info / low / medium / high / critical`，默认 `high`。
含义：**达到该级别就返回退出码 1**。

退出码约定：

| 退出码 | 含义 |
| --- | --- |
| 0 | 未达到阈值（或 `--fail-on none`） |
| 1 | 达到阈值 |
| 2 | 参数错误、路径不存在、目标非法、基线读取失败 |

### 5.2 存量项目：先记基线

```bash
# 把现有问题记下来（本次不阻塞）
python3 security_scan.py --authorized --source src --write-baseline .security-baseline.json

# 之后只对新增问题报警
python3 security_scan.py --authorized --source src --baseline .security-baseline.json
```

指纹由「规则编号 + 文件名 + 命中代码」计算，行号移动不会失效。
修完问题后重新生成基线，或手工删掉对应条目。

### 5.3 GitHub Actions

仓库里的 `.github/workflows/tests.yml` 会跑 68 项测试并扫描示例代码。
本仓库已启用，README 顶部的 `tests` 徽章就是它的实时状态：

```yaml
name: tests

on:
  push:
  pull_request:

jobs:
  unittest:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        python-version: ["3.10", "3.12"]
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: ${{ matrix.python-version }}
      - name: 运行单元测试
        run: python -m unittest -v
      - name: 扫描示例代码（预期退出码 1）
        run: |
          python security_scan.py --authorized --source examples || test $? -eq 1
```

两点注意：

1. **推送这个文件需要带 `workflow` 权限的 token**。经典 PAT 的 `repo` 权限不包含它，
   必须单独勾选 `workflow`，否则会报：
   `refusing to allow a Personal Access Token to create or update workflow ... without workflow scope`
2. 没有该权限时，也可以直接在网页上仓库 → Add file → Create new file，
   路径填 `.github/workflows/tests.yml`，把上面的内容粘进去提交。

### 5.4 其它平台

SARIF 是通用格式，GitHub Code Scanning、SonarQube、Azure DevOps 都能直接吃：

```bash
python3 security_scan.py --authorized --source src --format sarif --output report.sarif
```

## 六、忽略与规则

### 6.1 单行忽略

```c
gets(buf);              // security-scan: ignore
/* security-scan: ignore */
strcpy(dst, src);
```

当行或上一行写标记即可，C 用 `//`，Python 用 `#`。

### 6.2 目录忽略

在任意目录放 `.securityignore`，写法同 `.gitignore`：

```
vendor/
build/*.c
legacy_*.c
```

### 6.3 查看规则

```bash
python3 security_scan.py --list-rules                       # 终端表格
python3 security_scan.py --list-rules --format markdown     # 生成文档
```

规则清单也按 `docs/规则清单.md` 存在仓库里，由命令生成，不会和代码走偏。

## 七、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `CERTIFICATE_VERIFY_FAILED` | Python 缺 CA 证书（常见于独立安装的 Python） | 设置 `SSL_CERT_FILE=/etc/ssl/cert.pem`，或改用 `curl` 调 API |
| `认证失败（HTTP 401）` | API Key 错误或已失效 | 重新导出环境变量，重启服务 |
| `接口或模型不存在（HTTP 404）` | `--ai-base-url` 与 `--ai-model` 不匹配 | 对照厂商文档；DeepSeek 用 `deepseek-chat` |
| `未检测到 AI 凭证` | 没有设置 Key | 设 `SECURITY_AI_API_KEY` 后**重启**网页服务 |
| `端口 8765 无法监听` | 端口被占用 | `./run.sh --port 8800` |
| `禁止扫描私网、回环...` | 安全设计 | 本地目标请用单元测试的 mock 验证 |
| `基线文件不是合法 JSON` | 文件损坏或被手改 | 重新 `--write-baseline` |
| `ModuleNotFoundError: ai_advisor` | 只拷贝了部分文件 | 保持整个 `安全/` 目录完整 |
| `no tests ran` | 在错误目录执行 | 先 `cd 安全`，再 `python3 -m unittest` |
| 扫描结果为空 | 目标目录没有可扫后缀，或被 `.securityignore` 排除 | 用 `--min-severity INFO` 并确认路径 |

## 九、安全边界与免责

- 仅用于**自有或已获授权**的系统；`--authorized` 是强制项
- 不爬取、不爆破、不尝试利用；网络检查只请求入口页面
- 规则是行级正则，不做数据流分析，存在误报与漏报；AI 结论也需人工复核
- 扫描结果可能包含源码片段，报告与基线文件请勿随意公开
