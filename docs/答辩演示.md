# 答辩演示脚本

面向「软件安全性测试」课程汇报，全程约 5 分钟，不依赖网络（AI 部分除外）。

## 一、开场（30 秒）

> 这是一个面向 C 语言项目的安全自查工具：静态规则查危险 API，HTTP/TLS 检查查线上配置，
> 再把结果交给大模型翻译成风险说明和修复代码。全部用 Python 标准库实现，零第三方依赖。

打开界面：

```bash
cd 安全
./run.sh
```

浏览器会自动打开 `http://127.0.0.1:8765`。

## 二、演示扫描（90 秒）

1. 源码路径填 `examples`，点「开始扫描」。
2. 预期出现 **9 条结果**：CRITICAL 1、HIGH 4、MEDIUM 4，右侧按严重级别排序。
3. 指着 `SEC-101` 那条说：

   > `gets(name)` 在 `char name[32]` 上无长度限制，输入超过 31 字节就会覆盖栈上相邻变量，
   > 这是最经典的栈溢出（CWE-242）。工具直接给出了修复写法。

4. 再扫 `examples/safe_demo.c`，结果是「未发现任何结果」，说明不是见谁咬谁。

## 三、演示 AI 分析（60 秒，可选）

前提：已配置 API Key（`SECURITY_AI_API_KEY`），并重启过服务。

1. 回到 `examples` 的结果，点「生成 AI 分析」。
2. 展示输出结构：总体判断 → 逐条攻击路径 → 可直接替换的 C 代码。
3. 在追问框输入：「第二条和第三条有什么区别？」，展示上下文记忆。

> 提示词里只带命中行附近 3 行代码，密钥值会被替换成 `***`，所以不用担心源码外泄。

## 四、演示导出与集成（90 秒）

1. 点「导出 HTML 报告」，自动打开 `reports/security-report-*.html`，说明可以直接打印或提交。
2. 终端演示 CI 用法：

```bash
python3 security_scan.py --authorized --source examples --format sarif | head -20
echo $?    # 有 CRITICAL/HIGH 时为 1，可直接卡住流水线
```

3. 讲一句「存量项目怎么接」：

```bash
python3 security_scan.py --authorized --source examples --write-baseline .security-baseline.json
python3 security_scan.py --authorized --source examples --baseline .security-baseline.json   # 退出码 0
```

4. 展示规则清单（文档与代码同源，不会写错）：

```bash
python3 security_scan.py --list-rules
```

## 五、可讲的三个设计点（60 秒）

| 点 | 说法 |
| --- | --- |
| 规则可维护 | 17 条静态规则都带 CWE 编号和修复建议，加规则只改一个元组，测试自动覆盖 |
| 扫描器自己也安全 | 网络目标禁止内网/回环，关闭自动跳转防止 302 绕过；网页只监听本机并用一次性令牌校验 |
| AI 不乱来 | 只发命中片段、先脱敏、强制 HTTPS；没配 Key 或断网时扫描照常，退出码不变 |

## 六、常见提问

**问：正则匹配误报怎么办？**
答：行内 `// security-scan: ignore` 可以单条忽略；目录级 `.securityignore` 可以排除第三方代码；
误报本身也说明了行级规则的边界，所以 AI 分析那一步会明确提示「若判断为误报请说明理由」。

**问：为什么不用现成的 SonarQube / semgrep？**
答：课程目标是理解「检测原理 + 安全编码」，自己实现规则引擎才能说清 CWE 到代码模式的映射；
输出 SARIF 后也可以直接接进 SonarQube，两者不冲突。

**问：AI 会不会编造漏洞？**
答：提示词限定只能依据给出的代码和扫描结果，并要求标注误报；结论仍需人工复核，报告页脚也写了这一点。

**问：能扫别的语言吗？**
答：通用规则覆盖 Python/JS/Java/Go 等 20 多种后缀，C/C++ 规则单独限定后缀，避免跨语言误判。
