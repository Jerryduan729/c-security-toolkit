# 跨平台运行与打包

这个工具是纯 Python 标准库实现，三种用法按环境选一种即可：

| 方式 | 需要 Python | 适合 |
| --- | --- | --- |
| 源码运行 | 3.10+ | 自己改规则、看代码 |
| 免安装可执行文件 | 不需要 | 交作业、给别人演示、没有 Python 的电脑 |
| 自行打包 | 3.10+ 与 PyInstaller | 想要自己的平台专属版本 |

当前发布的免安装版本（在 Releases 页面下载）：

| 平台 | 命令行程序 | 网页界面 | 架构 |
| --- | --- | --- | --- |
| macOS | `security-scan-macos-arm64` | `security-toolkit-web-macos-arm64` | Apple Silicon |
| Windows | `security-scan-windows-x64.exe` | `security-toolkit-web-windows-x64.exe` | x64 |
| Linux | `security-scan-linux-x64` | `security-toolkit-web-linux-x64` | x86_64 |

> 没有代码签名，首次运行会被系统拦一下，按下面的步骤放行即可，不是文件损坏。
> 下载后可对照 `SHA256SUMS.txt` 校验完整性。

---

## 一、macOS（Apple Silicon）

### 1.1 首次运行

下载后放进任意目录（建议单独建一个文件夹，报告会生成在同级的 `reports/`）：

```bash
chmod +x security-scan-macos-arm64 security-toolkit-web-macos-arm64
xattr -d com.apple.quarantine security-scan-macos-arm64 security-toolkit-web-macos-arm64
```

如果提示 `无法打开，因为 Apple 无法验证`，也可以右键文件 → 打开 → 再点「打开」。

### 1.2 使用

```bash
./security-scan-macos-arm64 --version
./security-scan-macos-arm64 --authorized --source ./你的代码目录
./security-toolkit-web-macos-arm64            # 浏览器自动打开 http://127.0.0.1:8765
./security-toolkit-web-macos-arm64 --port 8800
```

`--ai` 等参数与源码版完全一致，AI Key 仍然从环境变量读：

```bash
export SECURITY_AI_API_KEY=sk-xxxx
./security-scan-macos-arm64 --authorized --source ./src --ai
```

### 1.3 架构说明

发布的是 **arm64** 版本，只能在 M1/M2/M3/M4 等 Apple Silicon 上运行。
Intel Mac 请用源码运行，或在 Intel 机器上自行打包（见第五节）。

> 这个版本在 Apple Silicon 本机构建（CI 的托管 macOS 运行器当前不可用）。

## 二、Windows（x64）

### 2.1 首次运行

把 `security-scan-windows-x64.exe`、`security-toolkit-web-windows-x64.exe`
放进同一个文件夹（例如 `D:\security-toolkit\`）。

双击 `security-toolkit-web-windows-x64.exe` 时若出现蓝色 SmartScreen 窗口：

1. 点「更多信息」
2. 点「仍要运行」

这是因为没有购买代码签名证书，不是病毒。若杀毒软件误报（PyInstaller 打包的程序常被误判），
把文件夹加入白名单，或改用源码运行。

### 2.2 命令行用法（cmd / PowerShell）

```bat
cd /d D:\security-toolkit
security-scan-windows-x64.exe --version
security-scan-windows-x64.exe --authorized --source D:\code\myproject
security-scan-windows-x64.exe --authorized --source . --format markdown --output report.md
security-toolkit-web-windows-x64.exe
```

PowerShell 里路径含空格要加引号：

```powershell
.\security-scan-windows-x64.exe --authorized --source "C:\Users\me\Documents\我的代码"
```

### 2.3 环境变量

```bat
set SECURITY_AI_API_KEY=sk-xxxx
set SECURITY_AI_BASE_URL=https://api.deepseek.com/v1
set SECURITY_AI_MODEL=deepseek-chat
security-scan-windows-x64.exe --authorized --source . --ai
```

PowerShell：

```powershell
$env:SECURITY_AI_API_KEY = "sk-xxxx"
```

### 2.4 中文输出

程序启动时会把标准输出切到 UTF-8，所以中文不会乱码或崩溃。
如果旧版终端仍显示乱码，先执行 `chcp 65001` 再运行。

## 三、Linux（x86_64）

```bash
chmod +x security-scan-linux-x64 security-toolkit-web-linux-x64
./security-scan-linux-x64 --authorized --source ./src
./security-toolkit-web-linux-x64 --port 8765
```

程序动态链接 glibc，在主流发行版（Ubuntu 20.04+、Debian 11+、CentOS Stream 9+）上可直接运行。

## 四、从源码启动

已经装了 Python 3.10+ 的话，不需要打包：

```bash
# macOS / Linux
./run.sh
python3 security_scan.py --authorized --source examples
```

macOS 也可以在 Finder 里双击 `启动-macos.command`（首次同样需要右键 → 打开）。

Windows 双击 `启动-windows.bat`，脚本会自动找 `py -3` 或 `python`。
命令行等价于：

```bat
py -3 web_app.py --open
```

## 五、自行打包

三个平台用同一套配置，各平台各自打包（PyInstaller 不支持交叉编译）：

```bash
python3 -m pip install pyinstaller        # 或 python3 packaging/build.py --install
python3 packaging/build.py
```

产物在 `dist/`：

| 文件 | 用途 |
| --- | --- |
| `security-scan` / `.exe` | 命令行扫描器 |
| `security-toolkit-web` / `.exe` | 网页界面 |

打包配置在 `packaging/security_toolkit.spec`，两个入口分别对应 `security_scan.py` 与 `web_app.py`；
网页版会把 `web/index.html` 打进包里，运行时报告写到可执行文件旁边的 `reports/`。

也可以在 GitHub 上手动触发 CI 打包：仓库 → Actions → build → Run workflow，
跑完在 Artifacts 里下载对应平台的压缩包。打 `v*` 标签时会自动构建 Windows 与 Linux 版本。

## 六、常见问题

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| macOS 提示「已损坏，无法打开」 | 未签名 + 隔离属性 | `xattr -d com.apple.quarantine 文件名` |
| macOS 提示「无法验证开发者」 | 同上 | 右键 → 打开 → 再点「打开」 |
| `bad CPU type in executable` | 在 Intel Mac 上跑 arm64 版本 | 用源码运行，或自行打包 |
| Windows 蓝色 SmartScreen | 无代码签名 | 更多信息 → 仍要运行 |
| 杀毒软件报毒 | PyInstaller 单文件常见误报 | 加白名单，或改用源码 |
| 双击 `.bat` 闪退 | 没装 Python 或路径含特殊字符 | 在该目录打开 cmd 手动执行看报错 |
| 网页打不开 | 端口被占用 | `--port 8800` 换端口 |
| 报告找不到 | 打包版写在 exe 同级的 `reports/` | 去可执行文件所在目录找 |
| 中文路径报错 | 终端编码 | Windows 执行 `chcp 65001`，或用引号包住路径 |
| Linux 报 `GLIBC_2.xx not found` | 系统过旧 | 用源码运行，或在目标系统上自行打包 |

## 七、校验下载是否完好

```bash
shasum -a 256 -c SHA256SUMS.txt      # macOS；Linux 用 sha256sum -c
```

或者直接跑：

```bash
./security-scan-macos-arm64 --version       # 应输出 Security Toolkit 1.2.0
./security-scan-macos-arm64 --list-rules    # 应列出 17 条规则
```

能正常输出版本和规则，说明打包产物完整；再跑一次 `--source examples`，应得到 9 条结果。
